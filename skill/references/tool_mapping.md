# Claude Code 工具调用规范

本文件将 YouMind 的 `edit`/`write`/`proxyWrite` 工具路由逻辑，映射到 Claude Code 的 `Edit`/`Write`/`Read` 工具集。

## 路由决策树

```
用户请求
├── 要求创建新文档/文章/文件 → Write（新文件）
├── 要求修改现有文件的局部内容
│   ├── 能提供精确的旧文本锚点 → Edit
│   └── 无法提供精确锚点 / 修改范围大 → Write（覆盖）
├── 要求重写/全文替换 → Write（覆盖）
└── 需要读取文件内容才能判断 → Read → 再根据内容决定 Edit/Write
```

## Edit 工具规范

### 何时使用 Edit
- 修改范围小于文件的 50%
- 能指出文件中具体存在的文本段落
- 修复特定错误、更新具体数据、插入短段落

### old_string 提取规则
- **必须**从文件实际内容中复制，严禁凭记忆输入
- **必须**包含完整的行内容（从行首到行尾）
- **必须**保留所有空格、标点、换行
- **不要**包含行号前缀

### 常见错误
- 在 old_string 中"修正"了原文的错别字 → 匹配失败
- 删除了原文中的空格或换行 → 匹配失败
- 从中间开始匹配一行 → 匹配失败

## Write 工具规范

### 何时使用 Write（CREATE）
- 用户说"创建""新建""写一篇""生成"
- 目标文件不存在
- 用户明确要求全新内容

### 何时使用 Write（OVERWRITE）
- 用户说"重写""替换""全文修改"
- 修改范围超过文件的 50%
- 可靠锚点不存在或过于碎片化

### 覆盖前必须确认
- 文件路径正确
- 用户明确表达了覆盖意图
- 已备份或用户知晓覆盖风险

## Read 工具规范

### 何时使用 Read
- 编辑前需要查看最新内容
- 用户引用了文件但内容不确定
- 需要基于文件内容做决策

### Read 后必须做的
- 如果从 Read 结果中提取 old_string，必须原样复制
- 如果文件内容很长，只读取相关部分

## 图片与公式

- 所有图片使用标准 Markdown 语法：`![alt](url)`
- 不编造图片 URL
- 如果用户请求图片但未提供 URL，描述期望的图片位置或询问 URL
